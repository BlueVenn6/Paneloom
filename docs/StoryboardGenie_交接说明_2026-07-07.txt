一、用户的核心目标

用户正在做一个“根据剧本生成漫画分镜和图片资产”的本地桌面工具。

核心使用场景：
1. 用户上传或粘贴剧本、小说、旁白稿等文本。
2. 工具用 AI 分析全文，先生成项目设定，包括主角、配角、道具、场景、世界观、统一风格。
3. 如果用户没有现成人物/道具/场景参考图，工具应能用 AI 根据剧本自动生成“角色一致性参考图/资产图”。
4. 用户也可以手动上传已有参考图。
5. 生成核心资产后，再把剧本拆成漫画分镜。
6. 每个分镜生成图片时，要引用这些角色/道具/场景参考图，尽量保持角色一致。
7. 输出可以是：
   - 单张图：一张图片表现一个故事瞬间。
   - 条漫：一张竖图内有 3-5 个上下连续小格，形成漫画阅读节奏。
8. 输出比例要适配主流平台，例如：
   - 竖屏 9:16：Reels、Shorts、Stories、TikTok 风格视频
   - 竖版 4:5：Instagram 竖版信息流
   - 方图 1:1
   - 横屏 16:9
   - Pinterest 2:3
9. 后续用户会把这些图拿去做解说漫画旁白视频，但工具内暂时不需要视频功能。
10. 用户希望这个工具先做好桌面版，不急着做手机版，最后再打包成 Windows exe。

本地已测试：
- 1536x1024 横图副本可以被规范化成 1024x1792。
- 948x1659 非标准竖图也可以被规范化成 1024x1792。

2. 条漫生成质量

虽然已在提示词中加入硬约束，但图片模型可能仍偶尔生成单张插画。
如果仍不稳定，可以继续增强：
- 后端给条漫模式生成更结构化的 prompt，例如：
  “Panel A/B/C/D inside the image: ...”
- planning_service 在 webtoon_strip 模式下不要只写“3-5 个小格”，而是明确每个小格的动作：
  “小格1：建立场景；小格2：人物反应；小格3：转折；小格4：结果”
- 可让每个分镜的 prompt 内显式列出 mini-panels。


3. 旧分镜提示词仍可能混杂英文

用户非常在意语言一致性。
当前已有五语言 UI 检查，但内容生成出来的 prompt 仍可能因为模型或历史数据出现英文。
可以继续优化：
- 对中文剧本，planning_service 强制中文 prompt
- 不要在中文项目中生成 “Manga storyboard panel...” 这类英文开头
- 重写分镜时清洗旧英文模板


4. 角色一致性仍需进一步强化

当前逻辑：
- 项目参考图会作为 edit_image 的输入或提示词参考
- 项目设定会拼接进 shot prompt

后续可增强：
- 每个核心角色资产生成后，自动写入 project_bible.characters
- 生成分镜图时默认选中全部核心参考图
- 若用户取消选中，界面提醒“一致性会下降”
- 为每个角色保存姓名、外观、服装、道具、参考图文件名


5. 图片比例已硬校验，但构图仍可能不理想

当前会强制输出 1024x1792 等目标尺寸。
但如果模型返回横图，后端会裁切成竖图，可能损失内容。
