# AI、生成状态与排期联动验收修复（2026-07-11）

## 人工发现的问题

1. 模型设置旧测试访问图片中转的 `/models`，返回 `only accepts image API paths`，不能证明图片模型可用。
2. 导入新 PDF 后，工作台继续展示旧的本地优化、Bible、参考图和分镜。现场数据中 `story_optimization.source=local`，且优化稿与当前原稿完全相同。
3. 参考素材和分镜图片任务缺少可信耗时与终态说明；参考素材部分失败仍可能显示笼统完成。
4. 排期生成后的通用“已完成”提示容易被理解为创作任务完成，排期任务没有直接反映项目真实创作状态。

## 修复结果

- 模型测试改为两个真实结果：最小文字推理、用户确认后的一张低质量测试图。删除 `/models` 伪验证代码。
- 新剧本导入后保留旧资产，但将旧优化、Bible 和分镜标为过期；旧分镜禁止继续生成图片。
- AI 优化不再静默回退本地模板。供应商失败、离线、无效 JSON、缺失优化稿、原稿原样返回均明确失败且不保存。
- AI 优化结果记录来源、供应商、模型、耗时、分析时间、输入 SHA-256 和输出语言。
- Bible 分析、AI 分镜拆解失败时不再以本地结果冒充 AI 成功。
- 参考素材最多两路受控并行；任务显示真实累计秒数。零产物为失败，部分产物为部分完成并显示错误。
- 排期页新增从项目数据自动读取的六阶段看板：剧本、Bible、分镜、图片版本、镜头锁定、导出。手工发布排期明确标为可选。

## 图片耗时结论

单张图片的主要耗时来自外部供应商推理和返回。工作台无法在不改变模型、质量或供应商的前提下保证更短时间，也不应通过重复并发请求换取速度，因为会重复计费。当前已做的安全优化是：

- 参考素材生成由串行改为最多两路并行；
- 单图任务展示真实累计时间和明确终态；
- 不把无本地图片文件的响应标记为成功；
- 工作台比例继续作为图片请求和最终归一化尺寸来源。

## 第二轮人工验收修复

用户继续发现：模型测试永久等待、WebView2 下载按钮不落盘、风险对象按原始字典显示、分镜缺少复制入口、并发文案含义不清、超时自动重试可能重复计费、参考资产像叙事拼贴、网格列数容易被误解为生成数量、项目时长始终为零。

本轮修复：

- 文字和图片模型拆成独立真实探测。文字 120 秒、图片 210 秒前端结束等待，先完成的先显示；后端单飞锁阻止重复测试。
- 图片供应商请求上限从 600 秒降到 240 秒，删除超时后的自动第二次付费生成。
- 优化稿、参考图、生成图、网格 PNG、JSON/CSV/XLSX/SRT/HTML 均使用 Windows 原生另存为并原子写入。
- `risks` 规范为 `risk/solution` 结构，旧项目中的字典字符串也会转换为“风险/处理建议”。
- 每个分镜提供“复制分镜文本”，包含画面、提示词、负面提示词和修改备注。
- 明确区分分镜队列并发 1、参考资产并发最多 2，并用全局信号量保证图片供应商总并发不超过 2。
- 参考资产先由文字 AI 输出 1 至 8 项资产计划，用户看到名称、用途、张数后确认，之后才调用图片模型。计划区分角色三视图、表情动作、配角、场景和关键道具，禁止叙事拼贴图。
- 参考资产任务实时显示计划数、完成数、失败数和当前项；资产元数据持久化到项目 `metadata/reference_assets.json`。
- “列数”改为“导出时每行图片数”，明确只排列已有图片，并显示图片数与行数。
- 当前项目有效使用时间每 30 秒自动累计；窗口失焦、不可见或长期无操作时暂停。周期复盘优先读取自动有效时长，手工工时为补充。
- 自动进度中的导出阶段不再出现 `2/1`，多个导出文件仍表示阶段 `1/1`，实际数量保留在详情。
