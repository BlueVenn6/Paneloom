# Paneloom Windows 本地桌面产品审计

> 状态更新：本文是 P0 修复前的基线审计。桌面 P0 清零后的结论与测试证据见 `desktop_p0_closure_2026-07-10.md`；本文保留用于追踪原始问题，不再代表当前门禁状态。

审计日期：2026-07-10  
目标：Windows 本地优先、单用户、资产完全本地沉淀的 AI 漫画 / 动漫分镜桌面工具  
打包 / Release / 部署：未执行

## 1. 项目现状总评

当前代码适合作为 Windows 桌面产品的基础，但还不适合作为桌面 Beta 交付。React/FastAPI 核心链路、JSON/CSV 本地持久化、文档解析、图片生成客户端、版本选择、导出和复盘均为真实实现；本轮又完成了原生 WebView2 窗口原型、DPAPI 密钥存储、日志脱敏和镜头批准锁定。

真正的桌面阻塞仍在本地项目边界：17 个现有项目全部记录绝对 `project_path`，17 个已有输出镜头记录绝对 `output_path`；项目 JSON 位于 `db/projects`，参考图、生成图和导出却分别位于源码根目录的全局文件夹。用户不能选择一个自包含项目目录、移动后重新打开，也没有整项目备份/恢复。原生壳目前仍是开发原型，需要 Python 环境和预构建前端，不能作为最终用户双击交付物。

## 2. 技术架构地图

| 范围 | 真实实现 |
| --- | --- |
| 前端 | React 19.2.6、Vite 8.1.3、JavaScript/JSX、Lucide |
| 后端 | Python 3.12、FastAPI 0.116.1、Uvicorn 0.35.0 |
| 数据库 / ORM | 无；每项目 JSON + CSV，无 ORM |
| 状态 | React hooks；语言/当前项目 localStorage；创作工作区落后端 JSON |
| 路由 | 前端 hash；FastAPI APIRouter |
| 文件 / 图片 | 当前为源码目录下 `db/`、`assets/`、`exports/`，按项目 ID 分隔但不自包含 |
| AI 文本 | OpenAI 兼容、GLM、Gemini native HTTP 客户端 |
| AI 图片 | OpenAI 兼容 `/images/generations`、`/images/edits`；图片已改为原子落盘 |
| OCR | 扫描 PDF OCR 不存在且会明确拒绝；社交截图使用云端视觉模型，不是本地 OCR |
| 文档 | TXT、MD、SRT、CSV、文本 PDF、DOCX、EPUB、基础 RTF、HTML、XLSX |
| 导出 | JSON、CSV、XLSX、SRT、HTML、浏览器 Canvas PNG 网格、单图下载 |
| 身份/隔离 | 无登录，符合本地单用户定位；项目 ID 和目录分隔已验证 |
| 桌面 | 新增 pywebview 6.1 + Windows WebView2 原型；同一 Python 进程管理随机回环 Uvicorn 服务 |
| 移动 | 无应用；仅 Web 响应式样式，本阶段正确延后 |
| 密钥 | `%LOCALAPPDATA%/Paneloom/config/settings.json`，Windows 当前用户 DPAPI 加密 |
| 日志 | 每项目生成/失败 CSV；写入前深度脱敏；应用日志目录已预留在 LocalAppData |
| 写入可靠性 | JSON 临时文件原子替换 + 单文件 `.bak`；图片临时文件原子替换 |
| 并发 | 单进程项目/分镜/日志锁；不支持多后端进程并发写 |
| 测试 | 16 项 unittest、Python compile、Vite build、原生窗口 smoke |

推荐的最终目录边界：

```text
%LOCALAPPDATA%/Paneloom/
  config/settings.json       # DPAPI 密文
  registry/recent.json       # 只记录最近项目路径
  logs/ cache/ temp/

用户选择的 MyComicProject/
  project.paneloom.json      # schema_version + 项目元数据
  script/                    # 当前剧本和版本
  entities/                  # characters/scenes/props JSON
  storyboards/shots.json
  references/                # 角色/场景/道具/风格参考
  generated/<shot>/<version>/
  layouts/
  exports/
  backups/
```

项目内引用必须相对项目根目录；迁移应先复制到 staging、校验文件数和哈希、重写相对路径、完整打开验证，再登记新路径，不能原地破坏 17 个旧项目。

## 3. 核心业务流程图

```text
Windows 单用户
  -> 本地项目
     -> 剧本导入/编辑 -> 优化快照/接受/拒绝/撤销
     -> 项目 Bible（风格/角色文字/场景文字/道具/世界规则）
     -> 参考图（上传/生成/风格分析）
     -> 分镜拆解 -> Prompt 组装（Bible + 连续性 + 参考图）
     -> 云端图片 API -> 本地原子保存 -> 版本历史 -> 当前版本
     -> 批准并锁定（禁止覆盖/编辑/删除/换版）
     -> 网格/结构化文件/单图导出
     -> 排期、工时、发布指标记录和复盘
```

不存在独立 Character、Scene、Prop、Layout、Publication 实体；这些仍主要是项目级自由文本和文件名引用。

## 4. 已完成功能

- 项目创建、重新打开、重命名、归档、复制、可恢复删除。
- 剧本粘贴和 10 类真实文档解析；扫描 PDF 会诚实提示需要 OCR。
- 本地分镜拆解、AI 拆解、分镜 CRUD/排序、项目级自动保存。
- 故事优化结果保存、接受、拒绝、整版撤销和脚本快照。
- Bible 的角色、地点、道具/服装、世界规则、风格和负面 Prompt 进入生成 Prompt。
- 参考图上传校验、参考资产生成、风格分析、参考图编辑链路。
- 单张/队列生成、失败反馈、部分多比例结果保留、版本历史和版本选择。
- 镜头批准锁定：后端拒绝重生成、参考图编辑、换版、字段修改和删除；批量队列跳过。
- JSON/CSV/XLSX/SRT/HTML、单图和 PNG 网格真实导出。
- 排期、任务、工时、发布指标和复盘真实持久化。
- DPAPI 密钥迁移、前端遮罩、历史/新增日志脱敏。
- 原生窗口启动、随机 `127.0.0.1` 端口、单实例、同源 UI/API、关闭回收服务的架构原型。

## 5. 半完成功能

- 角色一致性：文字和参考图真实进入 Prompt，但没有结构化角色实体、镜头角色关联、服装/表情/动作版本。
- 场景/道具：项目级可保存和参与 Prompt，但不可按实体搜索、筛选、复用或依赖删除。
- 图片版本：已保存、选择和锁定；没有 A/B 对比、版本标签、批注和清理策略。
- 故事优化：有前后文本和整版接受/拒绝/撤销，无可视 diff、部分接受和完整版本树。
- 排版：只有固定网格和 HTML；无自定义格、气泡/旁白框、字体、安全区、高清 PDF/印刷输出。
- AI 任务：前端可停止未提交队列；已提交 HTTP 请求只能在桌面关闭时终止进程，无法协作式取消。
- 项目删除有磁盘回收目录但没有恢复 UI/API；整项目备份不存在。

## 6. 虚假 UI

当前未确认仍存在核心“点击即假成功”的按钮。此前已修复连接测试失败仍显示成功、两个生成入口走同一路径等问题。需要警惕的命名不是假执行，而是能力夸大：当前“资产库/生产归档”只是项目视图；社交平台只是手工指标分类，不是 API 发布；扫描 PDF 明确不宣称 OCR 成功。

## 7. 断裂流程

1. 项目不能由用户选择为一个自包含目录，也不能通过“打开文件夹/项目文件”重新登记。
2. 项目 JSON、参考图、生成图、导出分散在三个全局根目录；只复制项目目录会丢资产。
3. 绝对路径导致开发机位置变化后，历史版本选择会判定本地文件缺失。
4. 结构化角色/场景/道具没有与单镜头建立 ID 引用，连续性仍靠自由文本。
5. 选定镜头能锁定，但锁定状态尚未自动驱动排期任务、排版就绪和导出审计。
6. 原生壳是开发原型，尚未形成无需 Python/Node 的用户运行边界。

## 8. 当前桌面 P0

1. **自包含项目目录缺失**：17/17 项目有绝对 `project_path`；项目资产分散，项目移动/重新打开无产品入口。
2. **最终用户启动边界未完成**：原生壳验证通过，但当前仍需开发环境安装 pywebview 并预构建前端。
3. **真实 AI 验收未完成**：本轮未消耗用户配额，当前文本、文生图、参考图编辑未做一次性端到端验收。
4. **整项目恢复不足**：只有单文件原子写和少量 `.bak`，没有整项目快照、恢复入口或升级迁移回滚。
5. **活动 AI 关闭只完成代码防护**：会标记任务中断并硬退出，尚未用真实长请求验证“关闭后无残留且项目可重试”。

## 9. 当前桌面 P1

- 生成任务仅在进程内存，重启后只能把 `generating` 恢复为失败重试，不能续跑。
- 没有明确离线状态；云 AI 失败不阻塞本地编辑，但用户要等请求失败后才知道网络不可用。
- 没有项目 schema 迁移器、recent registry、打开项目/修复路径 UI。
- 无本地 OCR、文件监听、磁盘空间预检、缓存上限和日志轮转。
- 资产无标签/搜索/来源/版本/依赖图，跨项目复用只有“复制整个项目”。
- 排期未自动读取分镜完成、失败、待修改、已锁定状态。
- 五语言没有完整人工回归；前端无 lint/typecheck 配置。

## 10. 当前桌面 P2

- `StoryboardPage.jsx`、`i18n.jsx` 体积过大。
- 错误文本仍混合本地化 UI 和英文供应商消息。
- 分镜页面信息密度高；移动响应式可用但不应扩展为完整手机版。
- 原生 smoke 窗口销毁约需一分钟，开发验证速度较慢，不影响正常长期窗口但应优化关闭观测。

## 11. 已自动修复

- API 密钥从源码目录明文 JSON 迁移到 Windows 用户级 DPAPI 密文；旧文件替换为迁移标记。
- 供应商错误、原始响应和 CSV 日志统一脱敏；历史日志扫描后无 token 模式命中。
- 镜头增加 `approval_status`、`locked`、`locked_at`；锁定镜头不会被批量/单张/参考编辑覆盖。
- 图片下载和 base64 保存改为同目录临时文件 + 原子替换。
- 新增 pywebview/WebView2 桌面原型：随机回环端口、同源生产 UI、单实例、关闭服务。
- 活动 AI 关闭时标记 cancelled、恢复生成中镜头为可重试状态，并为桌面入口启用进程终止保护。
- 前端增加批准/锁定控制、锁定状态和禁用路径；生产构建通过。

## 12. 未解决问题

桌面 P0/P1 见第 8、9 节。未进行安装包、Release、正式部署或真实计费 AI 调用。

## 13. 资产沉淀系统评估

现有真实 MVP 资产是：项目 Bible、剧本快照、参考文件、生成图片版本、选定版本和镜头锁定。关系链 `Bible/参考图 -> Prompt -> 生成 -> 版本 -> 选定 -> 锁定 -> 导出` 已存在。

下一阶段必须做：结构化 Character/Scene/Prop 记录、每镜头 ID 引用、参考图元数据、来源/版本、搜索筛选、依赖删除、项目内稳定相对路径。服装、表情和动作先作为角色子记录，不要立即拆成六套独立全局库。跨项目资产库和模板市场延后。

## 14. 社交媒体系统评估

当前没有直接发布 API，也没有假的“发布成功”。有真实的手工平台指标记录和视觉模型截图提取。桌面 MVP 建议采用 B+C+D+E：平台尺寸/安全区导出包、可编辑标题描述标签、发布记录和复盘；不做 A 直接 API 发布。TikTok/抖音、Instagram、Shorts、小红书、Bilibili 只作为导出预设，按用户验证排序；X/Facebook 暂不投入。

## 15. 排期复盘模块评估

它不是纯 UI：会生成任务、保存工时/阻塞、记录发布指标快照并生成周/月复盘。但它目前是独立创作运营工具，未形成制作控制台。应重定义为：剧本完成、分镜待生成/失败/待修改/已批准锁定、排版就绪、导出计划；由真实镜头状态驱动，社交数据保持手工可选。

## 16. Web 版建议

React/Vite 继续作为桌面内部 UI 技术和开发预览方式，不再作为主要交付形态。FastAPI 只绑定随机 `127.0.0.1`，不开放局域网。浏览器模式保留给开发调试；最终用户不应接触 npm、Python、端口或 localhost。

## 17. Windows 桌面方案

| 方案 | 现有代码改动 | 运行时/体积 | Python OCR/GPU | 生命周期 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Tauri + Python sidecar | 中高；引入 Rust、sidecar 权限和双进程协议 | 壳小，但仍需携带 Python 后端 | 可行 | 必须监督 sidecar | 不作为当前首选 |
| Electron + Python sidecar | 中；React 复用最好但增加 Node/Chromium | 三者中最大 | 可行 | 主进程成熟但仍有 Python sidecar | 不适合当前单机最小改造 |
| 通用桌面壳管理 FastAPI | 中；取决于 Tauri/Electron | 仍是双进程 | 可行 | 端口、退出、升级都需额外协议 | 只是一种模式，不是最终选择 |
| **pywebview + 同进程 FastAPI** | **最小；React/Python 直接复用** | 依赖系统 WebView2，安装体积由 Python/AI 依赖主导 | **最自然** | **一个 Python 主进程管理本地服务** | **推荐** |

推荐 pywebview，不是因为“最轻”，而是因为现有业务和未来 OCR/GPU 均已在 Python 边界，避免再引入 Rust/Node 主进程和 Python sidecar。正式阶段需要固定 WebView2 Evergreen 检测/引导、冻结资源路径、签名升级策略和项目 schema 迁移测试。

技术比较依据：[Tauri sidecar 官方文档](https://v2.tauri.app/develop/sidecar/)、[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[pywebview 使用文档](https://pywebview.flowrl.com/guide/usage.html)、[Microsoft WebView2 分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。

桌面化最小改造范围：自包含项目层 + recent registry；相对资产解析路由；备份/恢复和 schema migration；桌面文件选择器/拖拽；活动任务退出验收；然后才是冻结 Python/静态前端和安装器。

## 18. 手机版建议

值得做但现在不做。未来只做移动伴侣：查看项目/任务/分镜、A/B 选图、批准/驳回、简短文本修改、评论和灵感记录。禁止把批量编辑、复杂 Prompt、资产管理、模型密钥设置、精细排版和本地大文件迁入手机端。

## 19. 应删除或避免

- 最终产品中删除“打开浏览器 + 固定 8000/5173”的用户入口；仅保留为开发脚本。
- 不增加直接社交发布图标、假进度和假成功。
- 不把“生产归档”宣传成完整 DAM。
- 项目迁移完成后删除 `project_config.project_path` 绝对路径和 shot/version 的绝对 `output_path`。
- 不开发完整手机版，不引入 SaaS 登录/多租户作为当前阻塞项。

## 20. 应新增

1. 自包含项目 manifest、相对路径解析、打开/迁移/复制/备份/恢复。
2. 结构化角色/场景/道具及镜头引用和 Prompt 组装。
3. 资产标签、搜索、来源、依赖删除和版本元数据。
4. 持久任务状态、离线指示、成本/限流、可取消请求或独立 AI worker。
5. 基础排版/文字框/安全区和平台适配导出包。
6. 排期与镜头锁定/失败/导出状态自动关联。

## 21. 应延后

- 直接社交 API 发布、OAuth、多人协作、云同步、多租户。
- 完整手机编辑器、企业级全局 DAM、模板市场。
- 本地大模型/GPU 推理；先保留 Python 扩展边界并完成项目可靠性。
- 正式安装包和 Release，直到本报告 P0 清零并完成独立打包阶段。

70 / 100。核心状态、错误、空状态、队列和版本选择可见；项目打开/迁移/恢复和离线状态仍缺，分镜页较长。

## 25. 桌面交付准备度评分

47 / 100。原生窗口架构验证和安全 P0 已修，但项目目录边界、整项目恢复、真实 AI 验收、最终用户运行边界仍阻止 Beta。

## 26. 交付门禁

`DESKTOP_LOCAL_BETA_READY = NO`

阻止 Windows 本地桌面 Beta 的问题：自包含/可迁移项目目录未完成；整项目备份恢复未完成；原生壳仍为开发原型而非无需运行时的用户入口；当前模型链未做一次真实验收；关闭真实运行中 AI 任务未做端到端验收。

`PUBLIC_SAAS_READY = NO`

这是未来参考：无认证、多租户、数据库、对象存储、远程任务和公网安全边界；不影响本轮桌面定位判断。

明确结论：**这个产品现在不能交付 Windows 本地桌面 Beta。**
